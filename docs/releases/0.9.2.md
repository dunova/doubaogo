# doubaogo 0.9.2

## 这一版修什么

**说多久，屏幕上就完整显示多少。** 0.9.1 为了不让输入框报错，只显示最后 160 个字，
前面的用 `...` 代替——这等于让你看不见自己刚说了什么。这是错的做法，本版已废弃。

现在：说完一句，那句话就变成输入框里正常的文字，一直留在屏幕上；只有你正在说、
还可能被改写的十几个字处于"待定"状态。全程不折叠、不省略、不丢字。

## 你实际会看到的变化

| 场景 | 0.9.1 | 0.9.2 |
|---|---|---|
| 说 20 字 | 正常 | 正常 |
| 说 500 字 | 只看到 `...` + 最后一段 | 全部 500 字按顺序都在屏幕上 |
| 说完松手 | 提示替换掉文字 | 文字保留，提示接在后面 |
| 逐字刷新 | 整段重绘，一蹦一蹦 | 已落定的字不再重绘，顺滑 |

## 为什么这样做

输入框（网页里的富文本编辑器）对"正在输入中的那段文字"有长度限制，太长就会报
`Cannot resolve a Slate node from DOM node` 并让输入框失效。真正的解法不是把文字藏起来，
而是**别让长文字一直停在"正在输入中"**：说完的句子落定为正文，待定的部分自然就很短。

## 升级

```bash
systemctl --user stop omarchy-fcitx5.service

sudo install -m 755 <构建产物>/fcitx5-vinput.so /usr/lib/fcitx5/fcitx5-vinput.so.new
sudo mv /usr/lib/fcitx5/fcitx5-vinput.so.new /usr/lib/fcitx5/fcitx5-vinput.so

systemctl --user start omarchy-fcitx5.service
```

**必须用 `install` + `mv` 原子替换，不能在服务运行时用 `cp` 覆盖**：被进程映射的
`.so` 就地改写会让进程当场段错误，2026-11-12 的桌面崩溃就是这样发生的。

## 验证

1. 说一段 400 字以上、中间有停顿的话
2. 屏幕上应始终能看到完整文字，没有 `...`，没有红字报错
3. 松手后文字不消失，尾部出现提示

## 回退

上游原版：`sudo install -m 755 /usr/lib/fcitx5/fcitx5-vinput.so.orig /usr/lib/fcitx5/fcitx5-vinput.so`
（回退后长句会在屏幕上折叠成 `头部...尾部`，且实时文字可见性更差，仅作应急）
