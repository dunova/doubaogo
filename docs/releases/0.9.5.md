# doubaogo 0.9.5 — 按键链路禁止换页：打字不再被 zram 拖慢

发布日期：2026-11-14
上一版：0.9.4

## 这一版做了什么

给 `install.py` 生成的全部 `doubao-*.service` 单元加上：

```ini
[Service]
MemorySwapMax=0
```

效果：键盘引擎（`ImeService.exe`）、`keyboard-host.exe`、broker 以及语音守护
整条输入链路**永远不会被换出到 swap**。

## 为什么

实测事故（2026-11-14）：系统开了 zram 压缩交换 + `vm.swappiness=150`，内核把
「看起来不活跃」的 Wine 输入法引擎大量换出——`doubao-keyboard.service` 换页峰值
470MB，其中 `ImeService.exe` 单进程 271MB 躺在 zram 里。每次按键走
`fcitx5 → keyboard_broker → keyboard-host.exe → ImeService.exe` 链路时，碰到
被换出的页就要先做 zstd 解压，表现为打字延迟、一顿一顿。

内核文档与社区实践一致认为：**控制应放在工作负载上（cgroup），而不是动全局
swappiness**。zram 本身是内存级交换，`swappiness=150` 对这套 zram+磁盘 swapfile
混合配置已经接近最优（官方认可区间 100~200），不需要改；真正的问题是输入法
这种对延迟敏感的进程不该被换出。

## 升级

重新运行安装器让单元文件带上新配置（或手动给现有单元加 drop-in）：

```bash
mkdir -p ~/.config/systemd/user/doubao-keyboard.service.d
printf '[Service]\nMemorySwapMax=0\n' \
  > ~/.config/systemd/user/doubao-keyboard.service.d/50-no-swap.conf
systemctl --user daemon-reload
systemctl --user restart doubao-keyboard.service
```

验证：

```bash
systemctl --user show doubao-keyboard.service -p MemorySwapMax   # 应为 0
cat /sys/fs/cgroup/user.slice/user-1000.slice/user@1000.service/app.slice/doubao-keyboard.service/memory.swap.max  # 应为 0
journalctl --user -u doubao-keyboard.service -n 5               # 应见 "Doubao keyboard ready"
```

## 代价与回退

整条链路常驻内存约 950MB（Windows 引擎刚性成本），`MemorySwapMax=0` 表示这
~950MB 永远占住物理内存，不再回收。16GB 内存的桌面完全够用；若内存吃紧可回退：

```bash
rm ~/.config/systemd/user/doubao-keyboard.service.d/50-no-swap.conf
systemctl --user daemon-reload
systemctl --user restart doubao-keyboard.service
```

回退后恢复原状：引擎在内存压力下可以被换出，打字可能重新出现卡顿。
