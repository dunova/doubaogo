# doubaogo 0.9.4 — 撤回 0.9.3：说话过程中重新看得见自己说了什么

发布日期：2026-11-12
上一版：0.9.3（已撤回）

## 这一版做了什么

把语音输入的显示方式**恢复到 0.9.2**：

- 说话过程中，屏幕上持续出现真实的文字，按顺序、连续、完整
- 没有 `...`，没有折叠，没有截断，没有「等整句说完再冒出来」
- 句子说完即成为输入框里的正文，只有最后还在改写的十来个字处于待定状态
- 按结束键后文字不消失，提示跟在文字后面

0.9.3 的做法（完全不创建组合区、只逐句插入）虽然不再崩溃，但把实时反馈拿掉了：
说话时输入框是空的，要等一句落定才一次性出现。这是功能倒退，本版回退。

## 为什么回退

语音输入的核心体验是「边说边看得见」。为了消除一个报错而让人看不见自己刚说的话，
是把问题从「报错」换成「不能用」，两者都不可接受。已在
`patches/fcitx5-vinput/README.md` 里写成硬约束：**任何让人看不见自己文字的方案，
无论是否消除报错，一律判为不合格。**

## 那个报错到底是谁的

`Cannot resolve a Slate node from DOM node: [object HTMLSpanElement]` 是宿主应用
（WorkBuddy 的对话输入框，基于 Slate 编辑器）自己抛出的断言：

- 这句话原文、以及 `data-slate-zero-width` 等 Slate 内部标记，都能在宿主程序包里找到
- 在输入法插件 `fcitx5-vinput.so` 里搜 `Slate`，命中 0 次

输入法只负责把文字写进输入框，没有能力抛出这句话，也没有能力修它。我们能做的是让
写进去的方式尽量温和（组合区保持很短、已说完的句子直接落定为正文），剩下的是宿主
编辑器的缺陷，需要它自己的维护者修。

## 升级

```bash
systemctl --user stop omarchy-fcitx5.service
sudo install -m 755 <fcitx5-vinput 源码目录>/build-gcc/src/addon/fcitx5-vinput.so \
     /usr/lib/fcitx5/fcitx5-vinput.so.new
sudo mv /usr/lib/fcitx5/fcitx5-vinput.so.new /usr/lib/fcitx5/fcitx5-vinput.so
systemctl --user start omarchy-fcitx5.service
```

安装后核对：

```bash
md5sum /usr/lib/fcitx5/fcitx5-vinput.so   # 应为 0d11188a2ee012bee919b755d6a55c19
```

## 验证

- 源码与 0.9.2 逐字一致，编译产物 `0d11188a…` 与 0.9.2 的二进制完全相同
- `ctest` 47/47 通过

## 回退

```bash
systemctl --user stop omarchy-fcitx5.service
sudo install -m 755 /usr/lib/fcitx5/fcitx5-vinput.so.orig /usr/lib/fcitx5/fcitx5-vinput.so
systemctl --user start omarchy-fcitx5.service
```

`.orig` 是上游原始件；回退后长句会在屏幕上折叠成 `头部...尾部`。
