## 这个版本修了什么

### 1. 长语音说完，网页输入框会报错 —— 已修

**原来**：说很长的语音（超过约三百字）时，网页输入框会弹出红色报错
`Cannot resolve a Slate node from DOM node: [object HTMLSpanElement]`，
要手动点「重试」才能继续。

**原因**：语音实时上屏时，把「已经说过的全部文字」反复整段写进输入框。说得越长，
这一整段就越长；当它跨过输入框内部的一行或一段时，网页编辑器就找不回自己的位置，
于是报错。**跟对话框容量无关，是这段文字的长度问题。**

**现在**：输入框里只实时显示最新的一段（约 160 字），完整内容在说完后一次性上屏。
说得再长也不会撑破输入框。

### 2. 按结束键时，已上屏的文字被清空 —— 已修

**原来**：说完按结束键，进入「正在优化」阶段，屏幕上刚说出来的文字会整体消失，
只剩一句提示。

**现在**：文字保留在原处，提示**接在文字后面**显示，不再清屏。

### 3. 语音前端的改动纳入版本管理

语音的实时上屏部分由一个外部插件（`fcitx5-vinput`，GPL-3.0）承担。我们此前对它的
改动只存在于某个人的工作目录里，没有版本历史——上面第 1 个问题正是这样漏出去的。

从 0.9.1 起，这些改动以补丁序列的形式存放在本仓库 `patches/fcitx5-vinput/`，
随源码包一起分发，可用 `git am` 复现。

## 升级方式

```bash
# 1. 取回本版本源码与补丁
git pull

# 2. 应用补丁到插件源码（首次或版本变更时都要做）
git clone https://github.com/xifan2333/fcitx5-vinput
cd fcitx5-vinput && git checkout 5808fd0
git am /path/to/doubaogo/patches/fcitx5-vinput/*.patch

# 3. 构建并替换插件
cmake -S . -B build-gcc -G "Unix Makefiles" -DCMAKE_BUILD_TYPE=Release \
      -DVINPUT_ENABLE_LOCAL_ASR=OFF -DVINPUT_ENABLE_WERROR=OFF \
      -DCMAKE_INTERPROCEDURAL_OPTIMIZATION=OFF
TMPDIR=~/.cache/vinput-build-tmp make -C build-gcc -j"$(nproc)"
sudo cp /usr/lib/fcitx5/fcitx5-vinput.so /usr/lib/fcitx5/fcitx5-vinput.so.bak-$(date +%Y%m%d-%H%M%S)
sudo cp build-gcc/src/addon/fcitx5-vinput.so /usr/lib/fcitx5/fcitx5-vinput.so

# 4. 重启输入法使其生效
systemctl --user restart omarchy-fcitx5.service
```

## 验证

- 说一段 500 字以上的语音：输入框不应再报错。
- 按结束键的瞬间：文字应留在原位，其后出现「正在优化」提示。
- `ctest`：vinput 侧 47/47 通过；本仓库 `pytest` 66 项通过。

## 回退

```bash
sudo cp /usr/lib/fcitx5/fcitx5-vinput.so.bak-<时间戳> /usr/lib/fcitx5/fcitx5-vinput.so
systemctl --user restart omarchy-fcitx5.service
```

## 已知限制

- 实时预览只显示尾部约 160 字，前面折叠为 `...`；完整文本在提交时一次性上屏。
  若宿主编辑器允许，可调大 `kMaxInlinePreeditChars`（不建议超过 300，那正是会崩的区间）。
- 本仓库自带的 `doubaovoice` 插件（`fcitx5/voice.cpp`）做了同类修复，但当前语音链路
  走 fcitx5-vinput，它是待命状态。
