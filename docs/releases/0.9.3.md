# doubaogo 0.9.3

## 这一版改了什么

**听写不再往输入框里写「正在输入中」的那层文字。** 说完的话直接作为正文插进去，
就像你用键盘打字一样；只有最后几个字会等它稳定（约几百毫秒）再出现。

## 为什么又要改一次

0.9.2 的假设是「组合区太长才会崩」，于是把组合区缩到十几个字。**实测推翻了它**：
一句三十来个字的短话，照样弹出

```
Cannot resolve a Slate node from DOM node: [object HTMLSpanElement]
```

说明关键不是长度，是**组合区这个东西本身**。WorkBuddy 的输入框用的是 Slate 编辑器，
它每次收到组合区更新都要把这层文字重新解析回自己的文档模型；听写的更新频率远高于
手打拼音，它就解析到一个已经被下一次更新替换掉的节点，于是报错。

所以：截到 160 字不行，截到 12 字不行，折叠成 `头部…尾部` 更不行。**唯一的稳办法是
不创建组合区。**

## 你实际会看到的变化

- 说话过程中，屏幕上持续出现**真实的、已确定的文字**，不闪烁、不重绘
- 没有 `...`，不折叠，不丢字
- 最后几个字会略慢一点点出现（等识别结果稳定）
- 输入框不再弹红字报错

## 关于「豆包官方的单段限制」

查了火山引擎的语音识别文档：**流式识别没有「单段最多多少字」这种限制**，它是按音频
时长和连接时长约束的（录音文件识别是 ≤5 小时、<512MB；流式靠 VAD 分句和强制判停）。
所以「把我们的限制对齐到豆包官方」没有对应项可对齐——之前那个 48 字上限是我自己拍的，
和豆包无关，本版已经删掉了。

## 升级

```bash
systemctl --user stop omarchy-fcitx5.service
sudo install -m 755 <构建产物>/fcitx5-vinput.so /usr/lib/fcitx5/fcitx5-vinput.so.new
sudo mv /usr/lib/fcitx5/fcitx5-vinput.so.new /usr/lib/fcitx5/fcitx5-vinput.so
systemctl --user start omarchy-fcitx5.service
```

必须用 `install` + `mv` 原子替换；不要在服务运行时 `cp` 覆盖（会让进程当场崩溃）。

## 回退

`sudo install -m 755 /usr/lib/fcitx5/fcitx5-vinput.so.orig /usr/lib/fcitx5/fcitx5-vinput.so`
（先停服务）
